# Безопасность Ласточки

## Сравнение с Element Desktop (Element Classic)

| Защита | Element Desktop | Ласточка 3.0 |
|---|---|---|
| Сквозное шифрование сообщений (Olm/Megolm) | matrix-sdk-crypto (Rust) | та же библиотека |
| Подтверждение устройств и собеседников (эмодзи), кросс-подпись | есть | есть |
| Резервная копия ключей, ключ восстановления, экспорт/импорт ключей | есть | есть (формат совместим) |
| База ключей на диске зашифрована ключом из Связки ключей / DPAPI | есть | есть |
| Токен входа хранится зашифрованным | есть | есть |
| Песочница, contextIsolation, CSP, запрет webview и навигации | есть | есть |
| Electron Fuses (нельзя запустить как Node, подключить отладчик, подменить код в .app/.exe) | есть | есть |
| DevTools выключены в сборке | можно включить | выключены |
| Отображение сообщений | HTML (санитайзер) | только текст — HTML не выполняется |
| Подпись Apple / Microsoft, нотаризация | есть | ad-hoc подпись + SHA-256 файлов |
| Автообновления | есть | нет — пересборка раз в месяц (`npm run harden && npm run dist`) |
| Независимый аудит, программа bug bounty | есть | нет |

Последние три строки — организационные, кодом их не закрыть: нужны платный сертификат разработчика,
сервер обновлений и внешний аудит.

## Что не шифруется (свойство протокола Matrix)
Кто с кем и когда переписывается, названия и аватары комнат, список участников, фото профиля,
картинки стикеров из набора. Всё это сервер видит и в Element.

## Проверка
- ☰ → «Шифрование и ключи» → «Проверка безопасности».
- Правый клик по сообщению → «Шифрование сообщения»: алгоритм, устройство отправителя, шифротекст.
- На сервере (PostgreSQL Synapse) сообщения должны иметь тип `m.room.encrypted`:
  ```sql
  SELECT e.type, LEFT(ej.json, 200) FROM events e JOIN event_json ej USING (event_id)
  WHERE e.room_id = '!ID:ваш-сервер' ORDER BY e.stream_ordering DESC LIMIT 5;
  ```
- Целостность установщика: сравните SHA-256 файла с `release/SHA256SUMS.txt`
  (`shasum -a 256 Lastochka-*.dmg` на Mac, `certutil -hashfile Lastochka-Setup-*.exe SHA256` на Windows).

## Рекомендации
- Обновлять Ласточку раз в месяц: в Electron встроен Chromium, его уязвимости закрываются только новой сборкой.
- Включить FileVault (Mac) / BitLocker (Windows).
- Сохранить ключ восстановления, подтвердить собеседников в важных чатах.
- Synapse держать обновлённым, регистрацию закрытой, доступ только по HTTPS.

## Автоудаление сообщений: настройка Synapse

Ласточка удаляет исчезающие сообщения сама: у получателей они скрываются точно в срок, а приложение
отправителя удаляет их с сервера. Чтобы сервер подчищал базу и тогда, когда отправитель не в сети,
и не хранил удалённое ещё 7 дней, добавьте в `homeserver.yaml`:

```yaml
retention:
  enabled: true
  allowed_lifetime_min: 1h
  allowed_lifetime_max: 1y
  purge_jobs:
    - longest_max_lifetime: 1d
      interval: 15m
    - shortest_max_lifetime: 1d
      interval: 6h

# удалённые (redacted) сообщения стирать из базы через час, а не через 7 дней
redaction_retention_period: 1h
```

Перезапустите Synapse: `systemctl restart matrix-synapse` (или `docker restart synapse`).
Включая автоудаление в чате, Ласточка сама выставляет политику хранения комнаты (`m.room.retention`),
так что сервер стирает сообщения этого чата не позже срока (минимум 1 час — сервер чистит базу по расписанию).
Политика действует и на сообщения из Element.

## Звонки: TURN-сервер для Synapse

Звонки идут напрямую между устройствами (WebRTC, шифрование DTLS-SRTP). Если собеседники в разных сетях
за NAT, нужен TURN-сервер, иначе соединение может не установиться («Не удалось соединиться»).
Ласточка не использует чужие публичные серверы, только TURN вашего Synapse.

1. Установите coturn на сервер: `apt install coturn`. В `/etc/turnserver.conf`:
   ```
   use-auth-secret
   static-auth-secret=ДЛИННЫЙ_СЛУЧАЙНЫЙ_СЕКРЕТ
   realm=ваш-сервер.ru
   listening-port=3478
   min-port=49160
   max-port=49200
   no-cli
   no-tcp-relay
   denied-peer-ip=10.0.0.0-10.255.255.255
   denied-peer-ip=192.168.0.0-192.168.255.255
   denied-peer-ip=172.16.0.0-172.31.255.255
   ```
2. В `homeserver.yaml`:
   ```yaml
   turn_uris: ["turn:ваш-сервер.ru:3478?transport=udp", "turn:ваш-сервер.ru:3478?transport=tcp"]
   turn_shared_secret: "ДЛИННЫЙ_СЛУЧАЙНЫЙ_СЕКРЕТ"
   turn_user_lifetime: 86400000
   turn_allow_guests: false
   ```
3. Откройте на межсетевом экране порт 3478 TCP/UDP и диапазон 49160–49200 UDP,
   перезапустите coturn и Synapse.
